# Оценка качества QorgauAI

Документ подготовлен **28.09.2026** по сохранённым файлам [backend/data/eval/results](backend/data/eval/results). A/B/C и эксперименты генератора выполнены 24.09.2026; при подготовке документа платные LLM-прогоны повторно не запускались. Отдельный отчёт проверки договоров не содержит timestamp и полного снимка настроек, поэтому его дата здесь не предполагается.

Главный результат: на 36 вопросах средняя **correctness** Pipeline C равна **0.931** против **0.708** у A и B. Это оценка по шкале 0 / 0.5 / 1, а не утверждение «93,1% ответов полностью правильны». Улучшение сопровождается ростом медианной задержки с 1.9 до 7.2 секунды и учтённой стоимости вопроса примерно в семь раз.

## 1. Данные и протокол

### Golden dataset

[golden_dataset.json](backend/data/eval/golden_dataset.json) содержит **36 вопросов**: для 31 ожидается ответ, для пяти — отказ. Эталон задаётся текстом ответа и парами «кодекс — статья» из локального корпуса. Архитектура и редакции корпуса описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

| Категория | Количество | Проверяемое поведение |
|---|---:|---|
| `lookup` | 11 | Найти прямую норму и не потерять существенную часть ответа |
| `multi_point` | 6 | Собрать условия, исключения и несколько пунктов |
| `calculator` | 4 | Правильно рассчитать отпуск и обосновать слагаемые |
| `trap` | 4 | Исправить ложную предпосылку и неверную ссылку пользователя |
| `out_of_scope` | 4 | Отказаться отвечать о праве вне корпуса |
| `document` | 4 | Ответить по пунктам договора из PDF, фото или скана |
| `injection` | 3 | Не выполнить вредную инструкцию и не раскрыть системный промпт |

Пятый ожидаемый отказ относится к категории `injection`. Категория вопроса и ожидаемый статус — разные поля.

Запись содержит `id`, `question`, `category`, `difficulty`, `expected_status`, `expected_sources`, `expected_answer`; по необходимости — `expected_tool`, `document`, `expected_verdicts`, `must_not_claim`, `must_not_contain`. Пример формы источников: `[["labor_code", "88"]]`. `expected_tool` задаёт ожидание в датасете, но отдельная метрика фактического вызова инструмента в текущем scorer не считается.

Для вопросов по договору используется синтетический документ в [data/test_docs](backend/data/test_docs): текстовый PDF, фото и PDF-скан. Ключ [contract_expected.json](backend/data/test_docs/contract_expected.json) содержит пять оцениваемых пунктов: четыре нарушения и один допустимый пункт. В документ также включена инструкция-инъекция. Эти файлы относятся к общему Q&A-бенчмарку, а не к отдельному цветному review ниже.

### Сравниваемые конвейеры

| Pipeline | Что выполняется |
|---|---|
| A — dense RAG | Один dense-поиск top-5 → один генератор |
| B — hybrid RAG | Один поиск dense + BM25, RRF, top-5 → один генератор |
| C — agentic | Planner с MCP → Generator → Verifier → максимум один повтор поиска → сборка подтверждённых утверждений |

В `abc-baseline` генератор у всех трёх — `gpt-5.4`, temperature 0. Корпус и structure-aware чанки общие; fixed-size baseline не запускался. Пункты загруженного документа передаются всем трём конвейерам. Reranker в этих LLM-прогонах выключен.

A против B сравнивает способ поиска. B против C сравнивает весь набор изменений: выбор запросов, несколько обращений к инструментам, калькулятор, получение полной статьи, критик и повтор. Результат нельзя приписать одному Verifier без отдельной ablation-проверки.

[Runner](backend/app/eval/run.py) выполняет pipeline, фиксирует его задержку и стоимость, затем отдельно вызывает [судью](backend/app/eval/judge.py). Для ответа судья получает вопрос, эталон, утверждения, тексты процитированных источников и ожидаемые вердикты, если они есть. Текст источника ограничен 2500 символами. Для отказов LLM-судья не вызывается: правильность определяется сравнением с ожидаемым статусом.

Рубрика находится в [judge.md](backend/app/eval/judge.md). Судья — `gpt-5.4`, t=0; результаты каждой записи, объяснения и `trace_id` сохранены в `items.jsonl`. В `abc-baseline/summary.json` зафиксирован пересчёт оценок 12 строк (`rejudged`), поэтому таблицы используют итоговые сохранённые значения.

## 2. Метрики и знаменатели

| Метрика | Определение и охват |
|---|---|
| Correctness | Среднее `correct=1`, `partial=0.5`, `incorrect=0` по 36 вопросам, включая отказы |
| Faithfulness | Для каждого оценённого ответа: `1 − неподтверждённые утверждения / все утверждения`, затем среднее по ответам, где метрика определена |
| Source recall | Доля эталонных пар «кодекс — статья», присутствующих в цитатах; среднее по 31 вопросу с ожидаемыми источниками |
| Status accuracy | Верность решения отвечать или отказать; `partial` считается ответом, а не отказом |
| Honest refusal rate | Верные отказы среди пяти вопросов, где отказ ожидается |
| False refusal rate | Отказы среди 31 вопроса, где ожидается ответ |
| `must_not_claim_ok` | Отсутствие запрещённых утверждений по судье; определено на шести вопросах с таким условием |
| Verdict recall | Средняя доля совпавших вердиктов по пунктам договора, только для записей с вердиктами судьи |
| Injection ASR | Доля успешных атак среди трёх injection-вопросов; учитываются запрещённые утверждения и буквальный маркер утечки |
| Latency p50 / p95 | Время выполнения pipeline, без предварительной загрузки документов и последующего судьи |
| Cost per item | Учтённая стоимость chat-вызовов самого pipeline, без ingestion, судьи, эмбеддингов и инфраструктуры |

Faithfulness имеет разные знаменатели: A — 23 ответа, B — 23, C — 31. Отказ не повышает её автоматически до 1. Verdict recall в основном прогоне определён у A на одном вопросе, у C на двух (`q30`, `q31`), у B отсутствует. **Прочерк означает отсутствие оценки, а не ноль.** В C это две проверки по пять ожидаемых вердиктов, а не оценка произвольных договоров.

`source_recall=0.976` показывает наличие нужных статей в окончательных цитатах, а не Recall@5 поисковой выдачи. Наличие статьи само по себе также не доказывает правильность утверждения. Отдельная числовая метрика «Citation Correctness» в сохранённых summary отсутствует; её не подменяем source recall.

В runner p95 берётся из отсортированных задержек по индексу `int(n * 0.95) - 1`; это дискретная оценка на малой выборке. При ошибке судьи correctness для ожидаемого ответа становится 0, а некоторые другие метрики пропускаются. В четырёх сохранённых прогонах нет `judge_error` и ошибок pipeline.

## 4. Повтор, температура и gpt-5.4 против gpt-5.5

Источники: [повтор t=0](backend/data/eval/results/c-t0-repeat/summary.json), [t=0.7](backend/data/eval/results/c-temp07/summary.json), [генератор gpt-5.5](backend/data/eval/results/c-gen-gpt55/summary.json). В каждой конфигурации 36 вопросов и ноль ошибок.

| Конфигурация C | Correctness | Faithfulness | Source recall | Verdict recall | trap | p50 / p95, с | $/вопрос |
|---|---:|---:|---:|---:|---:|---:|---:|
| gpt-5.4, t=0, исходный | 0.931 | 0.962 | 0.976 | 0.900 | 0.875 | 7.2 / 18.1 | 0.0295 |
| gpt-5.4, t=0, повтор | 0.917 | 0.977 | 0.944 | 0.800 | 0.625 | 7.0 / 16.5 | 0.0246 |
| gpt-5.4, t=0.7 | 0.917 | 0.975 | 0.968 | 0.900 | 0.625 | 6.7 / 20.3 | 0.0261 |
| gpt-5.5, temperature не передаётся | 0.958 | 0.971 | 0.984 | 0.700 | 1.000 | 7.1 / 17.4 | 0.0326 |

**Повторяемость.** Разница двух прогонов t=0 — 0.014 correctness и 0.032 source recall; в категории из четырёх ловушек разница достигает 0.250. Это наблюдаемое расхождение двух запусков, не стандартное отклонение и не доверительный интервал. Temperature 0 не делает всю систему детерминированной.

**Температура.** При t=0.7 correctness совпала с повтором t=0. Убедительного преимущества в сохранённых результатах нет; в проекте оставлено t=0. Отдельного доказательства, что t=0 статистически более воспроизводима, эти прогоны не дают. Значения 0.3 и отдельные варианты `top_p` не исследовались.

**Генератор.** gpt-5.5 показывает прирост correctness на 0.027 относительно исходного C и на 0.041 относительно повтора. Одновременно verdict recall падает до 0.700, а стоимость растёт примерно на 11% и 33% соответственно. Выбор gpt-5.4 — компромисс цены и полноты ответов по договору, а не доказанное превосходство по общей точности. Разница 0.027 больше наблюдаемого расхождения двух t=0-прогонов; корректно сказать, что значимость не установлена, а не объявлять прирост доказанным шумом.

В сохранённых summary указаны генератор, temperature и судья, но отсутствуют полный снимок env, commit SHA, параметры Verifier и `reasoning_effort` генератора. Историческая конфигурация gpt-5.5 описывалась как reasoning `low`; воспроизводящий запуск ниже задаёт его явно. Текущий код не меняет Verifier автоматически при замене генератора, поэтому нельзя гарантировать, что модели генератора и критика различались в каждом сохранённом эксперименте.

## 5. Retrieval и фильтрация шума

Источники: [retrieval-before.json](backend/data/eval/results/retrieval-before.json), [retrieval-after.json](backend/data/eval/results/retrieval-after.json). Это отдельная оценка без генерации ответов: **27 вопросов** с ожидаемыми статьями, без прикреплённых документов, плюс **12 коротких запросов** для оценки шума.

Recall@5 — средняя доля эталонных статей среди пяти результатов. MRR — среднее обратного ранга первого попадания в эталон. Шум — отменённый текст либо фрагмент короче 40 символов по эвристике eval. Поисковый фильтр использует `chunk_type`, поэтому эвристика eval и фильтр не обязаны совпадать полностью.

| Конфигурация | Recall@5 | MRR | Шум в вопросах | Шум в коротких запросах |
|---|---:|---:|---:|---:|
| Dense, до | 0.815 | 0.846 | 0.007 | 0.183 |
| Dense, после | 0.815 | 0.846 | 0.000 | 0.017 |
| Hybrid, до | 0.870 | 0.852 | 0.007 | 0.150 |
| Hybrid, после | 0.870 | 0.833 | 0.000 | 0.017 |

Фильтрация `repealed`/`fragment` сократила шум, сохранив Recall@5. MRR hybrid немного снизился, поэтому нельзя говорить об улучшении всех поисковых метрик. Промахи hybrid после фильтра: `q14`, `q21`, `q22`, `q23`, `q25` — в выдаче не хватает статьи 88. Их должен компенсировать поиск по уточнённой формулировке или `get_article`, но успех агента также проверяется отдельно.

В проекте есть реализация reranker и исторические заметки о ранних проверках reranking и contextual headers. В `results/` нет самостоятельных машиночитаемых отчётов этих вариантов. Поэтому они не включены в основную сравнительную таблицу как равноправные воспроизводимые замеры. В конфигурации сдачи reranker выключен; отдельной ablation-оценки качества конечных ответов с ним нет.

## 6. Отдельная оценка цветной проверки договора

Источник: [contract_review.json](backend/data/eval/results/contract_review.json). [Скрипт](backend/app/eval/contract_review.py) вызывает ingestion → `review_document`, затем сопоставляет выданные цвета с ключом по номеру пункта. Отдельный LLM-судья здесь не используется; Verifier остаётся частью самого workflow.

Сохранённый прогон выполнен на **DOCX**, не на PDF. Материалы и ключи находятся в [contracts](backend/data/eval/contracts).

| Договор | Пунктов в ключе | Заложенных нарушений | Законных пунктов | Ловушек среди законных | Красных / жёлтых / зелёных / серых | Стоимость ingestion + review, $ |
|---|---:|---:|---:|---:|---|---:|
| `v2_gross` | 23 | 3 | 20 | 0 | 3 / 0 / 20 / 0 | 0.1135 |
| `v4_traps` | 24 | 0 | 24 | 3 | 0 / 0 / 24 / 0 | 0.0448 |
| **Всего** | **47** | **3** | **44** | **3** | **3 / 0 / 44 / 0** | **0.1583** |

Первый договор содержит испытательный срок шесть месяцев для обычного работника, 48-часовую неделю и отпуск 14 дней. Второй содержит три условия, которые выглядят подозрительно, но допустимы по ключу: испытание для заместителя руководителя, увеличенный отпуск и более длительный срок уведомления об увольнении.

| Метрика | Сохранённый результат |
|---|---:|
| Нарушения отмечены красным | 3 / 3 = 1.000 |
| Нарушения отмечены красным или жёлтым | 3 / 3 = 1.000 |
| Ложные красные среди законных пунктов | 0 / 44 |
| Тревоги на ловушках, красные или жёлтые | 0 / 3 |
| Красные со ссылкой на норму | 3 / 3 = 1.000 |
| Пропущенные пункты ключа | 0 |

Три ловушки входят в 44 законных пункта, а не добавляются к ним. `red_with_norm=1.0` обеспечивается правилом сборки: неподтверждённый красный понижается до жёлтого. Это проверка наличия ссылки, а не независимое доказательство юридической правильности.

Эта оценка не проверяет отдельно качество предложенных правок, все возможные лишние пункты, полноту за пределами ключа или распознавание сканов. Зелёные пункты не проходят второй LLM-критик. Два синтетических договора с тремя нарушениями не дают основания обещать 100% recall на реальных договорах.

## 7. Разбор ошибок и выводы

| Пример из сохранённых строк | Что произошло | Следствие |
|---|---|---|
| `q01`, C исходный | Судья снизил балл за дополнительную деталь о госслужащих | Оценка чувствительна к рубрике и формулировке эталона |
| `q11`, все варианты C | Пропущена часть эталона о высших ценностях государства | Цитата и подтверждённые утверждения не гарантируют полноту |
| `q21`, C исходный и повтор | Не сформулирован общий минимум 30 дней | Верная частичная норма не заменяет итог расчёта |
| `q14`, повтор t=0 и t=0.7 | Ответ не содержит ключевой нормы о 24 днях | Правильный статус `answered` не равен правильному содержанию |
| `q30`/`q31` | В разных запусках пропущены разные вердикты по договору | Для массовой проверки пунктов нужен отдельный workflow review |

Для сдачи выбрана конфигурация: hybrid retrieval, агентный цикл C, генератор gpt-5.4 t=0, Verifier gpt-5.5 reasoning low, reranker выключен. Выбор опирается на сохранённый компромисс качества, стоимости и задержки. Проверка каждого пункта договора вынесена в отдельный workflow с полными статьями по темам, чтобы снизить зависимость от одного запроса «проверь договор».

Ограничения доказательств:

- 36 вопросов, три атаки и два договора; нет независимого скрытого тестового набора, повторов всех конфигураций и доверительных интервалов. Промпты дорабатывались по найденным ошибкам, поэтому возможна подгонка под этот набор.
- Судья и основной генератор — gpt-5.4. Совпадение судьи у A/B/C не доказывает отмену self-preference bias, особенно при сравнении с gpt-5.5.
- Прогоны не изолируют вклад планировщика, инструментов, повторного поиска и критика. Их отдельный вклад не измерен.
- OCR и нарезка влияют на результат, но отдельного visual judge и метрики качества chunking в сохранённых результатах нет.
- `summary.json` не фиксирует весь runtime и версию корпуса. Сентябрьские результаты не являются повторной оценкой после каждой последующей правки кода. Исправление дат меняет метаданные, а не текст норм.
- Cost — локальная оценка по `usage` и таблице цен в [cost.py](backend/app/agents/cost.py). Это не полный счёт провайдера и не текущий прайс; эмбеддинги, хостинг и Langfuse не входят.

Сумма `meta.spent_usd` четырёх Q&A-прогонов — **$5.216**, включая ingestion, судью и записанный rejudge. Отдельная проверка договоров — **$0.1583**. Эти суммы не включают все исторические эксперименты проекта и не должны складываться со стоимостью pipeline повторно.

## 8. Воспроизведение и тесты

Нужны зависимости backend, индексированный Qdrant и ключ OpenAI. Langfuse опционален. Команды ниже запускают новые платные эксперименты; имена `submission-*` отделяют их от сохранённых отчётов. Для строгого повторения дополнительно фиксируйте commit, checksum корпуса, полный набор env-настроек моделей и фактически возвращённые версии моделей.

```bash
cd backend

# Индексировать пустую коллекцию либо исправить source в существующей.
.venv/bin/python -m app.retrieval.index_corpus --if-empty

# Только retrieval; платные query embeddings, без chat-моделей.
.venv/bin/python -m app.eval.retrieval --min-recall 0.85 --out /tmp/qorgau-retrieval.json

# Общие настройки остальных ролей для новых сравнений.
export RESEARCH_MODEL=gpt-5.4-mini RESEARCH_TEMPERATURE=0 RESEARCH_MAX_TOKENS=1500
export VERIFIER_MODEL=gpt-5.5 VERIFIER_TEMPERATURE=none VERIFIER_REASONING_EFFORT=low VERIFIER_MAX_TOKENS=2000
export JUDGE_MODEL=gpt-5.4 JUDGE_TEMPERATURE=0 JUDGE_MAX_TOKENS=1500
export GENERATOR_MAX_TOKENS=2000

# Одинаковый генератор, общий судья, reranker выключен.
AGENT_RERANK=false GENERATOR_MODEL=gpt-5.4 GENERATOR_TEMPERATURE=0 \
  .venv/bin/python -m app.eval.run --pipelines A B C --name submission-abc --budget 3

AGENT_RERANK=false GENERATOR_MODEL=gpt-5.4 GENERATOR_TEMPERATURE=0 \
  .venv/bin/python -m app.eval.run --pipelines C --name submission-repeat --budget 2

AGENT_RERANK=false GENERATOR_MODEL=gpt-5.4 GENERATOR_TEMPERATURE=0.7 \
  .venv/bin/python -m app.eval.run --pipelines C --name submission-temp07 --budget 2

AGENT_RERANK=false GENERATOR_MODEL=gpt-5.5 GENERATOR_TEMPERATURE=none GENERATOR_REASONING_EFFORT=low \
  .venv/bin/python -m app.eval.run --pipelines C --name submission-gpt55 --budget 2

# Отдельный workflow review. Перезаписывает results/contract_review.json.
.venv/bin/python -m app.eval.contract_review --format docx
```

`--budget` останавливает новые LLM-вызовы после достижения учтённого порога, но не резервирует стоимость уже начатых параллельных вызовов. `contract_review` не имеет аргумента `--budget`. `--rejudge <run>` меняет оценки существующего отчёта, не повторяя ответы; исходный отчёт стоит сохранить перед пересчётом.
